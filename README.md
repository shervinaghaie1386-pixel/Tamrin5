فعالیت فصل پنجم: تست، CI/CD و DevOps

نام پروژه: Smart Team Task Manager

۱. طراحی پنج Test Case

در این قسمت، پنج مورد از عملکردهای پروژه را آزمایش می‌کنیم:

شماره| مورد آزمایش| نتیجه مورد انتظار
۱| ثبت یک وظیفه جدید با اطلاعات صحیح| وظیفه با موفقیت ثبت شود.
۲| ثبت وظیفه بدون عنوان| سیستم اجازه ثبت ندهد.
۳| ورود با ایمیل و رمز عبور صحیح| کاربر با موفقیت وارد شود.
۴| تغییر وضعیت وظیفه به Completed| وضعیت وظیفه تغییر کند.
۵| حذف یک وظیفه| وظیفه از فهرست حذف شود.

۲. رسم نمودار Pipeline

مراحل اجرای Pipeline به ترتیب زیر است:

Code → Test → Build → Deploy → Monitor

- Code: نوشتن و ارسال کد برنامه.
- Test: آزمایش کد و بررسی عملکرد آن.
- Build: آماده‌سازی نسخه قابل اجرا از برنامه.
- Deploy: انتشار برنامه.
- Monitor: بررسی و نظارت بر عملکرد برنامه.

۳. در صورت شکست تست چه اتفاقی می‌افتد؟

اگر در مرحله Test خطایی پیدا شود، Pipeline متوقف می‌شود. سپس برنامه‌نویس باید خطا را برطرف کند و دوباره تست‌ها را اجرا کند. پس از موفقیت تست‌ها، مراحل بعدی ادامه پیدا می‌کنند.

۴. ارتباط Pipeline با Docker

Docker کمک می‌کند برنامه در یک محیط مشخص و استاندارد اجرا شود. در Pipeline می‌توان پس از موفقیت تست‌ها، با استفاده از Docker یک Image از برنامه ساخت و سپس آن را در قالب Container اجرا و منتشر کرد.

نتیجه‌گیری

استفاده از تست و Pipeline باعث می‌شود خطاهای برنامه زودتر شناسایی شوند و فرایند آماده‌سازی و انتشار نرم‌افزار منظم‌تر انجام شود. Docker نیز به اجرای برنامه در محیطی یکسان کمک می‌کند.
